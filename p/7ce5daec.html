Hello Fellow testers,

Rekluz Labs · 2026-09-05

Hello Fellow testers, I am the developer of Byways Media Hub @ Rekluz Labs. I wanted to share an update and some information on a subtle crash issue I've recently tracked down in Byways Media Hub when launched via the ACT Party launch button. I’m sharing the details here in case other devs run into the same thing in future. What happened: Byways would crash with a NullPointerException instantly upon being opened from ACT Party, but worked completely fine when launched directly on its own from the home screen. The root cause: Transparent Splash Icons: Like many apps that use custom full-screen splash artwork, Byways uses a transparent splash icon (windowSplashScreenAnimatedIcon). Different Launch Paths: When an app is opened directly from the home screen, Android always creates an icon reference (even if invisible). However, when launched externally from another app via startActivity (like ACT Party does), Android optimizes things behind the scenes and skips creating that icon reference entirely, returning null. Library Bug: Older versions of Google’s splash screen library (androidx.core:core-splashscreen v1.0.1 and lower) didn't handle null icon references gracefully and crashed when trying to access them. The fix: Good news. By updating to androidx.core:core-splashscreen:1.2.0 the issue is completely fixed! Google patched this behavior so it now handles null icons safely without crashing. If any other developers report their app crashing only when launched through ACT Party's Launch button, double-check if they use a transparent/invisible splash icon and if they're on an older version of core-splashscreen. Hope this saves someone else a bit of troubleshooting!
